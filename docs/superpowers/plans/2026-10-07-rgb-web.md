# RGB Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Publish a local-processing RGB virtual-fingertip instrument on GitHub Pages.
**Architecture:** A static operator page passes only current camera frames to an OpenCV worker. A shared geometry/protocol module validates calibration, transforms jointly solved fixture endpoints into body coordinates, gates observations, and records attempts locally.
**Tech Stack:** HTML/CSS/JavaScript, pinned OpenCV.js 4.13, IndexedDB, Node's test runner, Playwright, GitHub Pages Actions.
**Spec:** `docs/superpowers/specs/2026-10-07-rgb-web-design.md`

## Global Constraints

- One calibrated RGB camera, local processing, no uploads, no depth/AI claims.
- Millimeters; positive body Y superior; signed score is lower Y minus upper Y.
- Current observed poses only; one common pose per fixture; noncoplanar supported geometry.
- Three accepted trials in at most five attempts; one continuous second median; 15-second provisional timeout; pre/post seating checks.
- Missing calibration blocks metric output; unvalidated quality profiles allow exploratory estimates only.
- Explicit optional RGB consent/export; durable researcher exports supplement evictable browser storage.
- Use relative assets under the GitHub Pages project path.

## Review Focus

- Camera/frame configuration changes must invalidate incompatible calibration.
- Planar/ill-conditioned or conflicting observations must not become accepted measurements.
- Hidden page, pending permission, worker error, stale reply and role swap must not resume/score implicitly.
- Quota failures must stop the attempt without silently losing required evidence.
- Published static assets and runtime must work under the repository subpath.
